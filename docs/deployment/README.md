# デプロイメントドキュメント

福岡あそびアプリケーションのデプロイメント関連ドキュメントです。

## 📚 ドキュメント一覧

### 1. [ConoHa VPS セットアップガイド](./conoha_vps_setup.md)

ConoHa VPS 上に本番環境を構築するための完全ガイドです。

**内容:**
- VPS の初期設定（Ubuntu 22.04）
- セキュリティ設定（SSH、ファイアウォール）
- Ruby、Nginx、MySQL のインストール
- アプリケーションのセットアップ
- systemd サービスの設定
- SSL 証明書の設定（Let's Encrypt）
- GitHub Actions の設定

**対象者:** インフラエンジニア、初回セットアップを行う担当者

### 2. [デプロイ手順書](./deployment_guide.md)

本番環境へのデプロイ手順を説明したドキュメントです。

**内容:**
- 自動デプロイ（GitHub Actions）の使い方
- 手動デプロイの手順
- ロールバック手順
- デプロイチェックリスト
- デプロイ後の確認項目

**対象者:** 開発者、デプロイ担当者

### 3. [トラブルシューティングガイド](./troubleshooting.md)

本番環境でよく発生する問題と解決方法をまとめたガイドです。

**内容:**
- サービス起動の問題
- データベース接続の問題
- Nginx の問題
- パフォーマンスの問題
- 画像アップロードの問題
- GitHub Actions の問題
- SSL 証明書の問題
- 緊急対応手順

**対象者:** 全員（問題発生時の参照用）

## 🚀 クイックスタート

### 初めてデプロイする場合

1. [ConoHa VPS セットアップガイド](./conoha_vps_setup.md) を参照して環境を構築
2. [デプロイ手順書](./deployment_guide.md) のデプロイチェックリストを確認
3. GitHub Actions でデプロイを実行

### 既にセットアップ済みの環境にデプロイする場合

1. コードを main ブランチにプッシュ
2. GitHub Actions が自動的にデプロイを実行
3. [デプロイ手順書](./deployment_guide.md) のデプロイ後確認を実施

### 問題が発生した場合

1. [トラブルシューティングガイド](./troubleshooting.md) で該当する問題を検索
2. 解決方法を試す
3. 解決しない場合はチームに連絡

## 📋 デプロイメント構成

### アーキテクチャ

```
┌─────────────────────────────────────────────┐
│           インターネット                      │
└─────────────────┬───────────────────────────┘
                  │
                  │ HTTPS (443)
                  │ HTTP (80)
                  ▼
         ┌────────────────┐
         │     Nginx      │ ← リバースプロキシ
         │  (Let's Encrypt)│
         └────────┬───────┘
                  │ Unix Socket
                  ▼
         ┌────────────────┐
         │      Puma      │ ← Rails アプリサーバー
         │   (systemd)    │
         └────────┬───────┘
                  │
        ┌─────────┴──────────┐
        │                     │
        ▼                     ▼
  ┌──────────┐         ┌──────────┐
  │  MySQL   │         │  Local   │
  │          │         │  Storage │
  └──────────┘         └──────────┘
   データベース           画像ファイル
```

### サーバー構成

| コンポーネント | 用途 | ポート/パス |
|--------------|------|------------|
| Nginx | リバースプロキシ、静的ファイル配信 | 80, 443 |
| Puma | Rails アプリケーションサーバー | Unix Socket |
| MySQL | データベース | 3306 (localhost) |
| ActiveStorage | 画像ストレージ | /var/www/fukuoka_asobi/shared/storage |

### ディレクトリ構成

```
/var/www/fukuoka_asobi/
├── current/                     # アプリケーションコード（Git リポジトリ）
│   └── backend/
│       ├── app/
│       ├── config/
│       ├── db/
│       └── public/
├── shared/                      # 永続化データ
│   ├── .env.production         # 環境変数
│   ├── storage/                # 画像ファイル
│   ├── log/                    # ログファイル
│   │   ├── production.log
│   │   ├── puma_stdout.log
│   │   ├── puma_stderr.log
│   │   ├── nginx_access.log
│   │   └── nginx_error.log
│   └── tmp/                    # 一時ファイル
│       ├── pids/               # PID ファイル
│       └── sockets/            # Unix ソケット
└── releases/                    # (将来の拡張用)
```

## 🔧 主要な設定ファイル

| ファイル | 用途 | 場所 |
|---------|------|------|
| `nginx/fukuoka_asobi.conf` | Nginx 設定 | `backend/config/nginx/` |
| `systemd/fukuoka_asobi.service` | systemd サービス設定 | `backend/config/systemd/` |
| `.env.production.example` | 環境変数テンプレート | `backend/config/` |
| `database.yml` | データベース設定 | `backend/config/` |
| `storage.yml` | ActiveStorage 設定 | `backend/config/` |
| `puma.rb` | Puma 設定 | `backend/config/` |
| `deploy_vps.yml` | GitHub Actions ワークフロー | `.github/workflows/` |

## 🔐 セキュリティ

### 必須のセキュリティ設定

- [x] SSH 公開鍵認証の使用
- [x] root ログインの無効化
- [x] ファイアウォール（ufw）の設定
- [x] SSL/TLS 証明書の設定（Let's Encrypt）
- [x] 環境変数による機密情報の管理
- [x] 定期的なセキュリティアップデート

### セキュリティチェックリスト

デプロイ前に確認すべき項目：

- [ ] 環境変数に機密情報が含まれていないか
- [ ] データベースパスワードは強固か
- [ ] SSL 証明書は有効か
- [ ] ファイアウォール設定は適切か
- [ ] 不要なポートが開いていないか
- [ ] ログファイルに機密情報が含まれていないか

## 📊 監視とメンテナンス

### 推奨する監視項目

1. **稼働監視**
   - アプリケーションのヘルスチェック（/up エンドポイント）
   - HTTP ステータスコードの監視

2. **リソース監視**
   - CPU 使用率
   - メモリ使用率
   - ディスク使用率
   - ネットワーク帯域

3. **アプリケーション監視**
   - レスポンスタイム
   - エラー率
   - リクエスト数

### 定期メンテナンス

| 頻度 | タスク |
|------|--------|
| 毎日 | エラーログの確認、ディスク容量確認 |
| 毎週 | パフォーマンスレビュー、セキュリティアップデート確認 |
| 毎月 | データベースバックアップ、ログアーカイブ |
| 四半期 | セキュリティ監査、パフォーマンスチューニング |
