# プラン検索機能 設計書

## 1. 要件定義

### 1.1 概要
ユーザーが様々な条件を指定して、福岡県内の遊びプランを検索できる機能を実装する。
検索条件は「通常検索」と「カスタム条件」の2種類を用意し、ユーザーのニーズに合わせた柔軟な検索を可能にする。

### 1.2 画面構成
1. **検索条件の設定画面**
   - 通常検索タブとカスタム条件タブを切り替え可能
   - 通常検索では基本的な条件（エリア、日付、人数、予算）を指定

2. **カスタム条件の設定画面**
   - 詳細なオプションを指定可能
   - 移動手段、テーマ、雨天対応、イベント有無、出発地点、訪問スポット数、カテゴリー選択など

3. **エリア選択画面**
   - 福岡県の地図上から最大3つのエリアを選択可能

4. **日時と時間帯選択画面**
   - 日付、開始時間、終了時間を指定可能
   - 時間帯をスライダーで直感的に指定可能

### 1.3 機能要件
1. **通常検索条件**
   - エリア選択：福岡県内の地域から選択（最大3エリア）
   - 日付選択：訪問予定日を指定
   - 性別と人数選択：訪問者の性別と人数を指定
   - 予算範囲指定：予算の下限と上限を指定

2. **カスタム検索条件**
   - 移動手段：徒歩、電車、車、自転車など
   - 遊びのテーマ：癒し、アクティブ、コスパ、グルメ、自然、文化と歴史など
   - 雨天時対応：雨天でも楽しめるプランかどうか
   - イベント含有：イベントを含むプランかどうか
   - 出発地点：プランの開始地点
   - 訪問スポット数：プランに含まれるスポット数
   - カテゴリー選択：温泉、美術館、居酒屋、道の駅、体験、絶景など

3. **検索結果表示**
   - 条件に合致するプランのリスト表示
   - 各プランの基本情報（タイトル、スポット、総額など）を表示

## 2. 設計

### 2.1 全体構成

#### フロントエンド（Next.js）
- SSRを利用した高速な初期ロード
- Apollo Clientを使用したGraphQL通信
- コンポーネント設計による再利用性の高い実装

#### バックエンド（Rails & GraphQL）
- Ruby on Rails（APIモード）
- GraphQL Rubyを用いたAPI構築
- 既存のモデル（PlayPlan, Spot, Area等）を活用

### 2.2 画面設計

#### 2.2.1 検索条件設定画面
- タブ切り替えによる通常検索/カスタム条件の表示
- フォーム要素を使用した各種条件の入力
- 次へ進むボタンでエリア選択画面へ遷移

#### 2.2.2 エリア選択画面
- 福岡県の地図表示（SVGまたはマップライブラリ使用）
- クリックによるエリア選択（最大3つまで）
- 選択エリアのビジュアルフィードバック
- 次へ進むボタンで日時選択画面へ遷移

#### 2.2.3 日時選択画面
- カレンダーコンポーネントによる日付選択
- 時間帯選択用のスライダー
- 検索実行ボタン

### 2.3 コンポーネント構成

#### 共通コンポーネント
- `TabSelector`: タブ切り替え用コンポーネント
- `Button`: 汎用ボタンコンポーネント
- `RangeSlider`: 範囲選択用スライダー
- `DatePicker`: 日付選択コンポーネント
- `TimePicker`: 時間選択コンポーネント
- `AreaMap`: エリア選択用マップコンポーネント

#### 画面固有コンポーネント
- `SearchForm`: 検索条件入力フォーム
- `NormalSearchTab`: 通常検索タブの内容
- `CustomSearchTab`: カスタム条件タブの内容
- `AreaSelector`: エリア選択画面
- `DateTimeSelector`: 日時選択画面
- `SearchResults`: 検索結果表示

### 2.4 GraphQL設計

#### クエリ
```graphql
query getPlans($areaIds: [ID!], $date: String!, $genderInfo: GenderInput!, $budget: BudgetInput!, $customOptions: CustomOptionsInput) {
  searchPlans(
    areas: $areaIds
    date: $date
    genderInfo: $genderInfo
    budget: $budget
    customOptions: $customOptions
  ) {
    id
    title
    spots {
      id
      name
      category
      location
    }
    totalPrice
  }
}
```

#### 入力型
```graphql
input GenderInput {
  male: Int!
  female: Int!
}

input BudgetInput {
  min: Int!
  max: Int!
}

input CustomOptionsInput {
  transportationMethod: String
  theme: String
  rainyDayOption: Boolean
  includeEvents: Boolean
  startingPoint: String
  spotCount: Int
  categories: [String!]
}
```

### 2.5 バックエンド設計

#### GraphQLタイプ定義
- `PlayPlanType`: プラン情報を表現するタイプ
- `SpotType`: スポット情報を表現するタイプ
- `GenderInputType`: 性別と人数の入力を表現する入力タイプ
- `BudgetInputType`: 予算範囲の入力を表現する入力タイプ
- `CustomOptionsInputType`: カスタム条件の入力を表現する入力タイプ

#### リゾルバ
- `SearchPlansResolver`: 検索条件に基づいてプランを検索するリゾルバ

#### モデル連携
- 既存の`PlayPlan`、`Spot`、`Area`などのモデルを活用
- 検索条件に基づいたクエリ構築ロジックの実装
