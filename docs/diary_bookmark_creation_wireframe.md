# 日記（しおり）作成画面 ワイヤーフレーム設計書

## 1. 概要

### 1.1 背景
- ユーザーが福岡での遊び体験を記録・共有できる「日記（しおり）」機能の作成画面を設計
- Google Map上でのスポット管理、写真の添付、コメント入力を直感的に行えるUIを提供
- 作成したプランを公開・シェアする導線を明確化

### 1.2 主要機能
1. **スケジュール管理**: タイムライン形式でスポット訪問順序を管理
2. **地図表示**: Google Map上でスポットをビジュアル化
3. **写真管理**: 各スポットに複数の写真を添付・管理
4. **コメント入力**: スポットごとの感想・メモを記録
5. **公開・シェア**: SNS連携、URL共有機能

## 4. ユーザー利用フロー

### 4.1 作成フロー

```
1. 新規作成ボタンをクリック
   ↓
2. 基本情報入力
   • タイトル
   • 日付
   • 目的・タグ
   ↓
3. スポット追加（3つの方法）
   A. スポット名で検索 → 選択
   B. 地図上から選択
   C. 手動入力
   ↓
4. 各スポットの詳細入力
   • 訪問時間
   • 写真アップロード
   • コメント入力
   ↓
5. 移動情報の設定
   • 移動手段
   • 移動時間
   ↓
6. プレビュー確認
   ↓
7. 保存
   • 下書き保存
   • または公開
```

### 4.2 公開フロー

```
1. 作成完了した日記を開く
   ↓
2. [公開する]ボタンをクリック
   ↓
3. 公開設定画面
   • 公開範囲選択
     - 公開（全員）
     - 限定公開（URLのみ）
     - 非公開
   • タグ編集
   • サムネイル画像選択
   ↓
4. 確認画面
   • プレビュー表示
   • 最終確認
   ↓
5. [公開する]をクリック
   ↓
6. 公開完了
   • 公開URLが発行される
   • SNSシェアボタン表示
```


```ruby
# 既存のPlayPlanモデルを拡張
class PlayPlan < ApplicationRecord
  has_many :plan_details, dependent: :destroy
  has_many_attached :images # 複数画像対応
  
  # 新規追加フィールド
  # - map_center_lat: 地図の中心緯度
  # - map_center_lng: 地図の中心経度
  # - map_zoom_level: 地図のズームレベル
end

class PlanDetail < ApplicationRecord
  belongs_to :play_plan
  belongs_to :spot
  has_many :travel_details, dependent: :destroy
  has_many_attached :photos # スポットごとの写真
  
  # 新規追加フィールド
  # - comment: コメント（text型）
  # - photo_order: 写真の表示順序（jsonb型）
end
```

## 11. まとめ

### 11.1 推奨パターン

| 用途 | 推奨パターン |
|------|-------------|
| **初回作成（スマホ）** | パターンD（ステップ形式） |
| **日常的な作成（スマホ）** | パターンB（タブ型） |
| **詳細編集（PC）** | パターンA（3カラム） |
| **簡易編集（タブレット）** | パターンC（アコーディオン） |

### 11.2 実装優先順位

1. **Phase 1（MVP）**: パターンB（タブ型）+ 基本的なスポット追加・写真アップロード
2. **Phase 2**: パターンA（PC版3カラム）+ 地図連携
3. **Phase 3**: パターンD（ステップ形式）+ 初心者向けガイド
4. **Phase 4**: パターンC（アコーディオン）+ 高度な編集機能
